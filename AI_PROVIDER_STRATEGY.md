## Current implementation and reconciliation

The current Solo host is Python with a vanilla JavaScript interface. It needs no Vercel hosting migration, React rewrite, second simulator or external AI service to retain its existing supported operations. `IRGS_Web/features.py` labels the developer AI Network as planned; there is no connected provider or autonomous narrator. General freeform submissions still record unresolved declarations.

Retain exactly six Director categories: Game Master, World, National, Regional, Local and Scene. The proposed twelve responsibilities are logical task types, not twelve new Directors, twelve mandatory model calls or a dedicated Game Master specialist team. They cover coordination, character intent, dialogue, narration, scene composition, social reasoning, strategy, world reasoning, knowledge retrieval, memory, continuity and rules assistance. Reuse the existing planned registry/Capability Broker design instead of adding a competing coordinator or registry.

Core and its nine existing K-owners retain authoritative state. AI proposes actor intentions or derives presentation from authorized records. It cannot approve its own permissions, resolve an unsupported rule, invent a resource or commit a world effect. Preserve intent, permission, execution, information and presentation as separate stages. Character intent may be generated separately from its dialogue; expressive wording must not change the accepted intention or invent player actions.

Registry records are technical configuration, owned by Engine and administered through App server controls. Campaign listings must not select models, hold keys, authorize data transfer or certify a provider's terms.

## Task and recovery contract

A request identifies its task and attempt, logical responsibility, actor/scope, expected state revision, source/intent references, schema version, prompt version, permitted data classification, output limit, deadline and a finite cost reservation. Dispatch requires a configured approved route and a sufficient explicit budget; missing prices or unknown usage are not free inference. Budget reservations must account for concurrent calls and possible failed-attempt charges.

A result identifies the requested route and actual reported route separately, version certainty, usage certainty, timings, validation result and bounded error. Provider text is untrusted proposed output. Only the existing authorized Core operation can commit a supported effect, with the existing durable receipt/replay guarantees. Provider retries may incur multiple charges; accepted Core effects must still occur once. Timeout, cancellation, late completion, process restart, restore and stale state must not produce a second effect or silently authorize another paid call.

Fallback stays inside the explicitly eligible route list, deadline, retry limit, data policy and remaining budget. Gateway auto-routing is disabled unless its possible downstream routes satisfy the same constraints and actual route reporting meets the task's needs. Never put one gateway obligatorily in front of another. If none qualify, return unavailable or unresolved while retaining the player's exact intent.

Cache keys must include the relevant campaign/branch, actor scope, state/source revisions, permission policy, task/prompt/schema and model configuration. No cache may cross a knowledge boundary or resurrect an invalidated result. Memory summaries remain derived and linked to legitimate source records; mutable inventories and history stay in Core.

OpenAI direct access is the initial functional-integration candidate in the submission. GPT-6.1 Sol, Luna, Claude, Gemini, DeepSeek, Mistral, Mercury, GLM, MiniMax, Qwen, Kimi and other providers remain workload candidates. Verify an exact API ID and account availability before use; a model listed in research or exposed to Codex is not an IRGS API entitlement.

Vercel, OpenRouter and BLACKBOX are competing access options. Vercel's documented Python/HTTP compatibility makes it eligible for this host without changing the app stack; it has not won an IRGS comparison. Keep direct integrations for selected critical workloads so a gateway is replaceable. Dedicated hosting and fine-tuning follow measured demand; fine-tuning is never campaign-state storage.

Include denied information, prompt injection in reference content, unsupported effects, duplicate effects, stale output, timeouts, unavailable providers, exhausted budgets, disallowed fallback, route identity, rate changes, character intent, player agency and memory provenance. A schema-only validator or a mock response does not certify semantic fidelity or persistent autonomous simulation.

Existing DEV-06–DEV-08 dependency/recovery work and the first supported gameplay loop retain priority. Historical Details remains the active three-component integration cycle; its missing full archive is not resolved by provider planning. The component work orders carry these additional requirements as a sequenced backlog, and each chat continues pushing only its own repository. Planning-only commits do not count as viable component deliveries.

The coordinator reviews exact pushed commits and meaningful checks. Joined product integration still requires the existing three-component gate and compatible App pins. This addendum publishes requirements and research evidence only: no provider calls, paid accounts, new AI gameplay, campaign changes or component source imports are represented as completed work.
